# v0.1 Scope

## 목표
6주 안에 production-grade MVP 출시. Go 서비스에 import 해서 쓰는 라이브러리 모드 (HTTP proxy 모드는 v0.2).

## In Scope (반드시 포함)

### 1. Provider Abstraction
- OpenAI Chat Completions API
- Anthropic Messages API
- 통일된 인터페이스
  - `Provider.Chat(ctx, ChatRequest) (ChatResponse, error)`
  - `Provider.Name() string`
  - `Provider.SupportsModel(model string) bool`

### 2. Failover Routing
- Primary → Fallback 순서 지정
- Trigger: timeout, 5xx, rate-limit 응답
- 고루틴 + context propagation 기반
- Failover 시 metric 기록 (어디서 어디로, 왜)

### 3. Distributed Rate Limit
- Redis 백엔드
- RPM (requests per minute) + TPM (tokens per minute) 동시 적용
- Sliding window 알고리즘
- Lua script로 원자성 확보
- 분산락 패턴 (멀티 인스턴스 환경)

### 4. Observability (ADR-006 에서 land — 명세 차이는 ADR 결정이 우선)

**Metrics (Prometheus, `pkg/metrics/promrecorder`):**
- `llm_gateway_requests_total{vendor, model, outcome, origin}` — 모든 attempt
- `llm_gateway_failovers_total{from_vendor, to_vendor, reason}` — failover trigger
- `llm_gateway_unknown_model_total{vendor}` — Q7 cardinality alert
- `llm_gateway_attempt_duration_seconds{vendor, model, outcome}` — p50/p95/p99

**Structured logging (slog, `pkg/metrics/logrecorder`):**
- `request_id` (`internal/requestctx` 에서) + 6 표준 필드
- success → Info, error → Warn, failover → Info
- MultiRecorder 로 PromRecorder + LogRecorder 조합 가능

**v0.1 에 빠진 것 (v0.2 후속 ADR):**
- `llm_tokens_total{provider, model, type}` — token usage histogram. ADR-006 Q2 가 "v0.1 은 운영 baseline 만, token usage 는 cost ADR 후속" 으로 결정.
- `llm_cost_usd_total{provider, model}` — ADR-007 (cost attribution) 후보. Per-model pricing table + drift 운영 부담을 별 ADR 에서 다룸.

초기 scope 명세 (token/cost 포함) 와 ADR-006 결정 (제외) 의 drift 는 ADR 결정이 우선 — Q2 가 "정형화된 4가지 운영 dashboard 질문" 에 답하는 최소 셋으로 압축한 결과.

### 5. Documentation
- README (영문, RDD)
- ADR 6편 이상 (한국어 우선)
- Architecture diagram (mermaid 또는 excalidraw)
- examples/ 디렉토리 (3-5개 시나리오)

## Out of Scope (v0.2+)
| 항목 | 이유 |
|---|---|
| Semantic cache | 정확도 리스크 + 사용 사례 좁음. 벤더 prompt caching이 더 안전. |
| Streaming responses | 구현 복잡도 ↑, v0.1 검증 후 추가. |
| Embedding / Image / Audio | 사용 사례 다양, v0.2에서 모달리티별 추가. |
| Gemini / Bedrock / Vertex | 두 벤더로 패턴 검증 후 확장. |
| HTTP proxy 모드 | 라이브러리 모드 정착 후 추가. |
| Cost budget 가드 | rate limit 정착 후 위에 쌓기. |
| Cost attribution metric (`llm_cost_usd_total`) | ADR-007 후보. Per-model pricing table + drift 관리 부담 동반 — 별 ADR 에서 다룸. |
| Token usage histogram (`llm_tokens_total`) | ADR-006 Q2 결정 — v0.1 은 운영 baseline 만, token usage 는 비용 attribution (ADR-007) 과 함께 land. |
| A/B 라우팅 | 핵심 가치 아님. |

## 모듈 경계 (단방향 의존성)

다이어그램 버전: [architecture.md](architecture.md).

```
gateway/                    # 진입점: Config, New(), Chat()
├── pkg/
│   ├── provider/           # 벤더 추상화 (gateway는 이걸만 의존)
│   │   ├── openai/
│   │   └── anthropic/
│   ├── router/             # failover 라우팅
│   ├── ratelimit/          # 분산 rate limit
│   ├── metrics/            # Prometheus
│   └── logging/            # slog
├── internal/
│   └── testutil/           # recorded responses, mock Redis 등
├── examples/               # 사용 예시
└── docs/                   # 본 문서들
```

**원칙:** 각 `pkg/*`는 다른 `pkg/*`를 모를 수 있어야 한다. 합성은 최상위 `gateway` 패키지에서만.
